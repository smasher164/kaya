# Capture research: Windows (WinUI 3 / unpackaged Win32) and other toolkits

Research notes behind docs/capture-plan.md, web only (2026-10-01): no camera or microphone was opened on any host, VM, emulator or simulator for them. Bracketed notes mark inference.

Researched 2026-10-01, web only. Each bullet carries its source.

## 1. WinUI 3 camera preview and MediaCapture
- WinUI preview = Microsoft.UI.Xaml.Controls.MediaPlayerElement + WinRT MediaCapture; no CaptureElement in WinUI 3. Quickstart: enumerate with DeviceInformation.FindAllAsync(MediaDevice.GetVideoCaptureSelector()); pick a MediaFrameSource from mediaCapture.FrameSources with SourceKind==Color and MediaStreamType VideoPreview, else VideoRecord; `mediaPlayer.RealTimePlayback = true; mediaPlayer.Source = MediaSource.CreateFromMediaFrameSource(frameSource); mpe.SetMediaPlayer(mediaPlayer); Play()`. Preview render errors arrive on MediaPlayer.MediaFailed. https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-quickstart-winui3
- Init settings in the quickstart: VideoDeviceId, SharingMode (SharedReadOnly = view/capture only, ExclusiveControl = may change camera config; "Multiple apps can read from a camera simultaneously, but only one app at a time can have exclusive control"), StreamingCaptureMode (Audio / Video / AudioAndVideo), MemoryPreference (Cpu forces CPU memory; Auto lets system use GPU). Same URL.
- Quickstart template is "WinUI Blank App (Packaged)"; sample source github.com/microsoft/Windows-Camera/tree/master/Samples/MediaCaptureWinUI3. Same URL.
- Community Toolkit has a CameraPreview control wrapping MediaPlayerElement over frame source groups (CommunityToolkit.WinUI.Controls.CameraPreview). https://www.nuget.org/packages/CommunityToolkit.WinUI.Controls.CameraPreview
- MediaFrameSourceGroup.FindAllAsync() = sets of frame sources usable simultaneously (color/depth/IR/audio); select one via MediaCaptureInitializationSettings.SourceGroup. https://learn.microsoft.com/en-us/windows/apps/develop/camera/process-media-frames-with-mediaframereader
- MediaFrameReader: FrameArrived "raises the event on its own thread" (not the UI thread); pull with TryAcquireLatestFrame (may be null). MemoryPreference Cpu guarantees SoftwareBitmap; Auto may hand IDirect3DSurface instead. Sample converts to Bgra8/Premultiplied with SoftwareBitmap.Convert before display. AcquisitionMode Realtime (default for video) drops all but newest frame while the handler is busy; Buffered (1709+) keeps order. SharedReadOnly receives frames while another app holds the camera but cannot change settings; ExclusiveControl fails init if another app already has exclusive control. Same URL.
- Mic PCM via MediaFrameReader: Windows 10 1803+. MediaCapture with StreamingCaptureMode.Audio; pick FrameSources where MediaStreamType==Audio; check CurrentFormat Subtype (Float) and AudioEncodingProperties (e.g. 2ch/48000). Audio defaults to Buffered acquisition. FrameArrived -> AudioMediaFrame.GetAudioFrame() -> LockBuffer(Read) -> IMemoryBufferByteAccess::GetBuffer. Declare webcam + microphone (packaged). AudioDeviceController via MediaFrameSource.Controller (Muted -> zero samples). AudioFrame can feed AudioGraph's AudioFrameInputNode. https://learn.microsoft.com/en-us/windows/apps/develop/camera/process-audio-frames-with-mediaframereader
- Alternatives for mic: AudioGraph.CreateDeviceInputNodeAsync (AudioDeviceInputNode) https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/audio-graphs ; raw WASAPI IAudioClient capture https://learn.microsoft.com/en-us/windows/win32/coreaudio/capturing-a-stream
- Failure surfaces: MediaCapture.Failed (MediaCaptureFailedEventArgs: Code, Message) "Raised when an error occurs during media capture" https://learn.microsoft.com/en-us/uwp/api/windows.media.capture.mediacapture.failed ; MediaPlayer.MediaFailed for the preview (quickstart); MediaFrameReader.StartAsync returns MediaFrameReaderStartStatus (Success / UnknownFailure / DeviceNotAvailable / OutputFormatNotSupported / ExclusiveControlNotAvailable) https://learn.microsoft.com/en-us/uwp/api/windows.media.capture.frames.mediaframereaderstartstatus
- Codes: E_ACCESSDENIED 0x80070005 (privacy off) thrown as UnauthorizedAccessException from InitializeAsync, or from IMFActivate::ActivateObject in raw MF https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-privacy-setting ; 0xC00D3704 MF_E_HW_MFT_FAILED_START_STREAMING = hardware resources unavailable, typical when another app holds a non-shareable camera; in raw MF the source activates and the FIRST ReadSample fails (not activation) https://github.com/AprilNEA/OpenLogi/issues/1019 ; 0xA00F4244 NoCamerasAreAttached / 0xA00F4243 CameraReservedByAnotherApp are the Camera app's codes, not API HRESULTs https://support.microsoft.com/en-us/windows/hardware/camera/camera-app-shows-error-0xa00f4244-nocamerasareattached ; 0xC00DAFC8 MF_E_UNSUPPORTED_CAPTURE_DEVICE_PRESENT from InitializeAsync (1803+) https://learn.microsoft.com/en-us/uwp/api/windows.media.capture.mediacapture.initializeasync
- Prior art of the in-use crash: MAUI CameraView on Windows crashes the app when the camera is in use https://github.com/CommunityToolkit/Maui/issues/2520
- Hotplug: DeviceInformation.CreateWatcher(DeviceClass.VideoCapture / AudioCapture) -> DeviceWatcher Added/Removed/Updated/EnumerationCompleted https://learn.microsoft.com/en-us/windows/uwp/devices-sensors/enumerate-devices ; MediaDevice.DefaultAudioCaptureDeviceChanged for default-mic change https://learn.microsoft.com/en-us/uwp/api/windows.media.devices.mediadevice.defaultaudiocapturedevicechanged

## 2. Permissions and privacy
- Settings > Privacy & security > Camera: access "can be disabled for the entire device, for all unpackaged apps, or for individual packaged apps". Check with AppCapability.Create("Webcam").CheckAccess() == Allowed (doc says "For packaged apps"); handle E_ACCESSDENIED regardless; open ms-settings:privacy-webcam (mic: ms-settings:privacy-microphone); retry init after return. https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-privacy-setting
- Quickstart calls CheckAccess "Supported in Windows Build 18362 and later". https://learn.microsoft.com/en-us/windows/apps/develop/camera/camera-quickstart-winui3
- Packaged: <DeviceCapability Name="webcam"/> / "microphone" in Package.appxmanifest; first use shows a consent prompt. https://learn.microsoft.com/en-us/windows/uwp/packaging/app-capability-declarations
- Unpackaged (shipping Windows 11): one switch "Let desktop apps access your camera/microphone"; no prompt; denied => E_ACCESSDENIED. Registry: HKCU\...\CapabilityAccessManager\ConsentStore\webcam (Value Allow/Deny; NonPackaged subkey lists desktop exes with LastUsedTimeStart/Stop, which feeds "recently used"). https://davidarno.org/using-the-registry-to-monitor-webcam-and-microphone-use/ ; https://docs.velociraptor.app/exchange/artifacts/pages/windows.registry.capabilityaccessmanager/ (LastUsedTimeStop==0 while the app holds the device: a usable 'in use by whom' read)
- AppCapabilityAccessStatus (1903+): DeniedBySystem 0, NotDeclaredByApp 1, DeniedByUser 2, UserPromptRequired 3, Allowed 4. CheckAccess never prompts (may answer UserPromptRequired); RequestAccessAsync may prompt and never answers UserPromptRequired. Docs scope CheckAccess guidance to packaged apps; for unpackaged, unverified by docs what it answers, so treat E_ACCESSDENIED at init as the authority (measure on the VM). https://learn.microsoft.com/en-us/uwp/api/windows.security.authorization.appcapabilityaccess.appcapabilityaccessstatus
- NEW (Insider build 26340.9233, Experimental 26H2, Aug 2026): per-app camera/mic/location toggles for desktop apps, and desktop apps that have not used the resource "prompt for permission the first time access is requested". Not shipping GA as of this writing. https://www.bleepingcomputer.com/news/microsoft/microsoft-tests-new-privacy-controls-for-windows-11-desktop-apps/ ; https://www.windowslatest.com/2026/08/19/windows-11-is-getting-a-major-privacy-upgrade-blocks-apps-spying-on-your-camera-and-mic-with-new-controls/
- Privacy indicator: camera/mic icon in the taskbar tray while in use, hover names the app; Settings shows "Recent activity". https://support.microsoft.com/en-us/windows/windows-camera-microphone-and-privacy-a83257bc-e990-d54a-d212-b5e41beba857

## 3. Virtual camera / synthetic mic on Windows
- MFCreateVirtualCamera(type, lifetime, access, friendlyName, sourceId, categories, n, &cam): min client Build 22000 (Windows 11), mfsensorgroup.dll. Only MFVirtualCameraType_SoftwareCameraSource. sourceId = "{CLSID}" of a COM custom media source (user-mode DLL, no kernel driver). Lifetime_Session: gone when the IMFVirtualCamera is released/Shutdown; Lifetime_System persists across reboots. Access_CurrentUser per-user; Access_AllUsers needs admin. Pipeline appends "Windows Virtual Camera" to the name. Subject to the webcam privacy switch (E_ACCESSDENIED); packaged callers must not call it on the UI thread (consent deadlock). https://learn.microsoft.com/en-us/windows/win32/api/mfvirtualcamera/nf-mfvirtualcamera-mfcreatevirtualcamera
- The media source DLL runs inside the Frame Server service, so its COM registration must be in HKLM (admin, regsvr32) and the DLL in a directory the Frame Server / Frame Server Monitor services can read (not under a user profile). https://github.com/smourier/VCamSample (.NET port: https://github.com/smourier/VCamNetSample)
- Microsoft sample: github.com/microsoft/Windows-Camera Samples/VirtualCamera; Windows 11 SDK 22000+, installed by an MSI that registers the DLL in HKLM; session vs system lifetime both shown; no virtual-on-virtual, one wrapper per physical camera. https://github.com/microsoft/Windows-Camera/tree/master/Samples/VirtualCamera
- Frame Server custom media source (driver-docs background on what the DLL implements). https://learn.microsoft.com/en-us/windows-hardware/drivers/stream/frame-server-custom-media-source
- OBS virtual camera is a DirectShow source filter: DirectShow clients (Zoom, Chromium) see it, Media Foundation / MediaCapture clients (Windows Camera app, WinRT MediaCapture) do NOT. https://github.com/juniormartinxo/spiegel/issues/3 ; https://medium.com/deelvin-machine-learning/how-does-obs-virtual-camera-plugin-work-on-windows-e92ab8986c4e  => an MF-based capture backend needs an MF virtual camera (MFCreateVirtualCamera), not OBS, as its synthetic source.
- ARM64: OBS's DirectShow vcam is per-architecture COM registration; enabling arm64-native vcam disables it for x64-emulated apps and vice versa. https://obsproject.com/kb/windows-on-arm . An MF virtual camera's DLL is loaded into the Frame Server (a native arm64 service on Windows on Arm), so it must be built arm64 (inference from the hosting model; no doc states it, measure).
- Virtual mic: Windows ships none. VB-CABLE driver pack 45 (Oct 2024) supports Win10/11 ARM64; admin install + reboot (kernel driver; plays to "CABLE Input", records from "CABLE Output"). https://vb-audio.com/Cable/ . Open-source alternative (virtual speaker + mic): https://github.com/VirtualDrivers/Virtual-Audio-Driver . "Stereo Mix" exists only if the audio driver exposes it (not a given on a VM).
- No-device fallback test path: MediaCapture over a file is not a capture source; the honest synthetic sources are a registered MF virtual camera (video) and a loopback cable driver (audio).

## 4. Frame Server sharing
- Frame Server (FrameServer service) lets one "controlling" app plus any number of "shared" apps read one camera; shared apps get no camera controls, no media-type choice, video only (photo pins blocked); zero-copy. Stream must carry MF_DEVICESTREAM_FRAMESERVER_SHARED=1. https://github.com/microsoft/Windows-Camera/wiki ; https://learn.microsoft.com/en-us/archive/msdn-technet-forums/12de4147-9fa0-4031-818f-2cec9a1d080b
- API side: MediaCaptureSharingMode.SharedReadOnly (frames while another app holds it, no settings changes) vs ExclusiveControl (fails if another app already holds exclusive). MediaFrameReader.StartAsync -> ExclusiveControlNotAvailable (1703+). https://learn.microsoft.com/en-us/windows/apps/develop/camera/process-media-frames-with-mediaframereader ; https://learn.microsoft.com/en-us/uwp/api/windows.media.capture.frames.mediaframereaderstartstatus
- Windows 11 "Multi-app camera" (Settings > Bluetooth & devices > Cameras > Advanced camera options; also "Basic camera"; Group Policy Camera > Configure Camera Options): lets several apps stream one camera at once, built with the Hard-of-Hearing community; when on, some controls are settable only from Settings. Shipped via Release Preview 26100/26200 builds. https://learn.microsoft.com/en-us/windows-insider/release-notes/release-preview-24h2-25h2/build-26100-8514-26200-8514 ; https://www.anoopcnair.com/camera-options-in-windows-multi-app-and-basic/

## 5. Flutter `camera`
- Federated: endorsed camera_android_camerax (Android, SDK 24+), camera_avfoundation (iOS 13+), camera_web; Windows NOT endorsed. availableCameras() -> CameraDescription list; CameraController(desc, ResolutionPreset, enableAudio). Lifecycle "no longer handled by the plugin": the app disposes/re-inits in didChangeAppLifecycleState. Permission errors are CameraException codes: CameraAccessDenied, CameraAccessDeniedWithoutPrompt, CameraAccessRestricted, AudioAccessDenied, AudioAccessDeniedWithoutPrompt, AudioAccessRestricted. https://pub.dev/packages/camera
- Preview = Flutter Texture widget (external texture id); CameraX's Preview SurfaceProvider is wired to a TextureRegistry.SurfaceProducer surface. https://pub.dev/packages/camera_android_camerax/changelog ; https://github.com/flutter/packages/pull/6461 (SurfaceTexture -> SurfaceProducer migration)
- startImageStream(onAvailable): only where supportsImageStreaming; keeps "the latest image available ... and will drop all other images" (iOS/Android); throws if streaming or recording already started; frames are CameraImage planes (YUV420 / BGRA8888 / NV21 by ImageFormatGroup). https://pub.dev/documentation/camera/latest/camera/CameraController/startImageStream.html
- camera_windows: IMFCaptureEngine (Media Foundation), preview to a Flutter texture via TextureRegistrar; NO image streaming (flutter#97542), no exposure/focus, no pause/resume recording "due to Windows API limitations". https://pub.dev/packages/camera_windows ; https://raw.githubusercontent.com/flutter/packages/main/packages/camera/camera_windows/windows/capture_controller.h
- No audio stream API: "[camera] access to audio stream during video recording" open P3 since 2023-10. https://github.com/flutter/flutter/issues/136968 ; mic PCM comes from separate plugins (record, mic_stream). https://github.com/idaretobe/mic_stream

## 6. React Native VisionCamera (v4 and v5)
- v5 released 2026-04-16: Nitro Modules rewrite (Swift/Kotlin), outputs are separate HybridObjects created up front (CameraPhotoOutput.capturePhoto()), Formats replaced by declarative Constraints negotiated by the session, multi-camera via createCameraSession(true), depth output. https://margelo.com/blog/whats-new-in-visioncamera-v5
- Preview (v4): iOS PreviewView with layerClass = AVCaptureVideoPreviewLayer https://raw.githubusercontent.com/mrousavy/react-native-vision-camera/v4.7.3/package/ios/Core/PreviewView.swift ; Android androidx.camera.view.PreviewView; errors surface via onError / onInitialized view events https://raw.githubusercontent.com/mrousavy/react-native-vision-camera/v4.7.3/package/android/src/main/java/com/mrousavy/camera/react/CameraView.kt
- Frames (v5 "Frame Output"): onFrame runs synchronously on a parallel worklet runtime (react-native-worklets; v4 used react-native-worklets-core over JSI). Frame = GPU-backed buffer at full res/rate with width, height, pixelFormat ('yuv'|'rgb'|'native'), timestamp, orientation, toArrayBuffer(); small reusable pool: "if that pool is full, the pipeline stalls and subsequent frames will be dropped"; frame.dispose() mandatory. https://visioncamera.margelo.com/docs/guides/frame-processors
- Devices: useCameraDevices(), useCameraDevice('back' | 'front' | 'external'); imperative deviceFactory.cameraDevices + addOnCameraDevicesChangedListener; external = UVC hotplug, auto-updates. https://visioncamera.margelo.com/docs/guides/devices
- Permissions: useCameraPermission() / useMicrophonePermission() -> { hasPermission, requestPermission }; NSCameraUsageDescription / NSMicrophoneUsageDescription; android.permission.CAMERA / RECORD_AUDIO. https://visioncamera.margelo.com/docs/guides/permissions
- Closed error union (v4 CameraError.ts), "domain/code" strings: permission/{microphone,camera}-permission-denied; device/{configuration-error,no-device,invalid-device,microphone-unavailable,pixel-format-not-supported,camera-not-available-on-simulator,camera-already-in-use,...}; session/{camera-not-ready,audio-in-use-by-other-app,no-outputs,audio-session-failed-to-activate,hardware-cost-too-high,invalid-output-configuration}; system/{camera-module-not-found,camera-is-restricted,no-camera-manager,max-cameras-in-use,do-not-disturb-bug,...}; capture/* (23 codes); format/*; parameter/*; unknown/unknown. (No "session/camera-has-been-disconnected" in 4.7.3.) https://raw.githubusercontent.com/mrousavy/react-native-vision-camera/v4.7.3/package/src/CameraError.ts
- Mic: audio only as a track in video recording; no audio frame/PCM output documented in v4 or v5 (absence, not a quoted statement). https://visioncamera.margelo.com/docs/guides/frame-processors

## 9. Web reference (Media Capture and Streams)
- getUserMedia(constraints): secure context only; Permissions-Policy camera / microphone. Constraints: deviceId {exact}, facingMode "user"/"environment" (or {exact}), width/height {min, ideal, max}, frameRate {ideal, max}; bare value = ideal. Closed error set (DOMException names): AbortError (granted but device unusable for another reason), InvalidStateError (document not fully active), NotAllowedError (user/policy denied or insecure), NotFoundError (no track of that kind satisfies constraints), NotReadableError (OS/hardware error, e.g. device in use), OverconstrainedError (.constraint names the impossible one), SecurityError (user media disabled on the Document), TypeError (empty/all-false constraints). https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia
- enumerateDevices(): MediaDeviceInfo {kind videoinput/audioinput/audiooutput, label, deviceId, groupId}; labels EMPTY (and ids restricted) until permission granted or a stream is live; MediaDevices fires devicechange on add/remove. https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices
- MediaStreamTrack: enabled (app-controlled; false => black/silence, the right "mute"), muted (read-only, source not delivering; mute/unmute events), readyState live/ended, ended event (NOT fired for the app's own stop()), stop(), getSettings/getCapabilities/applyConstraints/getConstraints, clone(), contentHint. https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack
- Audio processing constraints echoCancellation (true/false/"all"/"remote-only"), autoGainControl, noiseSuppression; Baseline since 2020-01. https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/echoCancellation
- Permissions API: PermissionStatus.state "granted" / "denied" / "prompt", change event; names "camera" / "microphone". https://developer.mozilla.org/en-US/docs/Web/API/PermissionStatus/state
- Raw frames: MediaStreamTrackProcessor({track}).readable -> ReadableStream of VideoFrame (WebCodecs) or AudioData; dedicated-worker exposure per spec, Chrome also on window; not Baseline; discardedFrames/totalFrames counters; VideoFrame must be close()d. https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrackProcessor . Portable PCM path: MediaStreamAudioSourceNode -> AudioWorkletNode (process() on the audio rendering thread, 128-frame Float32 blocks). https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletProcessor/process
- Synthetic test sources (Chromium): --use-fake-ui-for-media-stream (auto-grant, no prompt); --use-fake-device-for-media-stream (test pattern for video; audio "default is to generate a beeping sound"); --use-file-for-fake-video-capture=file.y4m (or .mjpeg; header must say C420, not ffmpeg's C420mpeg2); --use-file-for-fake-audio-capture=file.wav. https://webrtc.github.io/webrtc-org/testing/ ; https://chromium.googlesource.com/chromium/src/media/+/refs/heads/main/audio/fake_audio_input_stream.h ; https://cyara.com/blog/y4m-video-chrome/
- The fake-device switch takes options: fps (5-60), device-count (0-10), ownership=client, config=<photo failure modes>, display-media-type, hardware-support=none|pan-tilt-zoom => scripted failure injection is prior art. https://raw.githubusercontent.com/chromium/chromium/main/media/capture/video/fake_video_capture_device_factory.cc
- WebRTC AEC location: Chrome runs the WebRTC Audio Processing Module (AEC/NS/AGC) itself, historically in the renderer (MediaStreamAudioProcessor), moved toward the audio service process ("APM in Audio Service") to run nearer the hardware without shipping buffers to renderers; the audio service is its own process on Windows/Mac/Linux. https://groups.google.com/a/chromium.org/g/feature-media-reviews/c/uC8kutdANzo/m/GA-1kx9SAQAJ ; https://groups.google.com/a/chromium.org/g/chromium-dev/c/W_aCc4qkpTI . APM source: https://chromium.googlesource.com/external/webrtc/+/lkgr/modules/audio_processing/include/audio_processing.h

## Design-relevant takeaways (my synthesis, not sourced claims)
- Windows preview for a WinUI backend has one documented route: MediaPlayerElement over MediaSource.CreateFromMediaFrameSource; frames via MediaFrameReader on its own thread; mic PCM via the same MediaFrameReader (1803+) keeps one API family.
- Unpackaged = no prompt and one global desktop switch (until the 26H2 per-app work ships): the closed failure vocabulary must have a "denied" member that arrives at start time as E_ACCESSDENIED, not from a pre-check.
- Error vocabularies seen: web (8 DOMException names), VisionCamera ("domain/code" union, ~60), Flutter (CameraException code strings), Qt/MAUI (one bucket + free string). The web set is the smallest closed set that still separates denied / not-found / in-use (NotReadable) / overconstrained.
- Synthetic sources for lanes: web = fake-device flags; Windows = an MF virtual camera (admin, HKLM, arm64 DLL) + VB-CABLE (arm64 OK); Qt 6.8 setVideoFrameInput/setAudioBufferInput shows a toolkit-level "app feeds the capture session" hook.

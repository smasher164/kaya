# Camera + microphone capture: Android and Linux (GTK4) — research notes 2026-10-01

Research notes behind docs/capture-plan.md, web only (2026-10-01): no camera or microphone was opened on any host, VM, emulator or simulator for them. Bracketed notes mark inference.


## ANDROID 1. CameraX
- Versions: CameraX stable 1.6.2 (2026-08-26), alpha 1.7.0-alpha03. `androidx.camera:camera-compose` stable 1.6.2 (in the same version train; which release first made it stable not pinned; CameraX 1.5.0 stable was 2025-09-10). https://developer.android.com/jetpack/androidx/releases/camera
- Flow: ProcessCameraProvider.getInstance(ctx) -> bindToLifecycle(owner, CameraSelector, useCases...). CameraSelector.DEFAULT_BACK_CAMERA / DEFAULT_FRONT_CAMERA; `.filter(cameraProvider.availableCameraInfos)` lists cameras. https://developer.android.com/media/camera/camerax/architecture
- PreviewView ImplementationMode: PERFORMANCE (default) = SurfaceView (hardware overlay, lower power/latency); COMPATIBLE = TextureView (blending, transforms). https://developer.android.com/media/camera/camerax/preview
- PERFORMANCE falls back to TextureView when: API <= 24, camera is CAMERA2_LEGACY hardware level, a SurfaceView device quirk (SurfaceViewStretchedQuirk / SurfaceViewNotCroppedByParentQuirk), or Preview target rotation != PreviewView display rotation (javadoc). Source `shouldUseTextureView`: https://raw.githubusercontent.com/androidx/androidx/androidx-main/camera/camera-view/src/main/java/androidx/camera/view/PreviewView.java
- Do not hand PreviewView's own SurfaceTexture/Surface to a SurfaceProvider; preview stops. https://developer.android.com/media/camera/camerax/preview
- Compose: `CameraXViewfinder(surfaceRequest, implementationMode=...)` in camera-compose (introduced 1.4 alpha, blog: https://android-developers.googleblog.com/2024/12/whats-new-in-camerax-140-and-jetpack-compose-support.html). Built on viewfinder-compose `Viewfinder`, which is AndroidExternalSurface for ImplementationMode.EXTERNAL (SurfaceView) or AndroidEmbeddedExternalSurface for EMBEDDED (TextureView). Source: https://android.googlesource.com/platform//frameworks/support/+/d3e410158459d11126787b37864e91ad073a91ca/camera/camera-viewfinder-compose/src/main/java/androidx/camera/viewfinder/compose/Viewfinder.kt
- viewfinder-compose/core/view stable 1.6.2; default mode now auto: prefers EXTERNAL (SurfaceView), falls back to EMBEDDED (TextureView) on older APIs / quirky devices; overridable. https://developer.android.com/jetpack/androidx/releases/camera-viewfinder
- ImageAnalysis: default STRATEGY_KEEP_ONLY_LATEST (single-slot, overwrites; other use cases see all frames); STRATEGY_BLOCK_PRODUCER queues (setImageQueueDepth) and stalls the whole camera. Formats OUTPUT_IMAGE_FORMAT_YUV_420_888 (default) or RGBA_8888 (CameraX converts; plane 0 bytes). Analyzer runs on the Executor passed to setAnalyzer; must ImageProxy.close(); one analyzer at a time. https://developer.android.com/media/camera/camerax/analyze
- Combinations: one each of Preview+VideoCapture+ImageAnalysis+ImageCapture allowed simultaneously; on hardware level FULL or lower, Preview+VideoCapture+(ImageCapture or ImageAnalysis) may trigger "stream sharing" (PRIV stream duplicated; more power/latency); LEVEL_3 not affected. Extensions guarantee only Preview+ImageCapture. Incompatible combos throw at session creation. https://developer.android.com/media/camera/camerax/architecture
- External cameras: CameraSelector.LENS_FACING_EXTERNAL is @ExperimentalLensFacing (added 1.3.0); treated like front-facing, little verification. Works only if the device's camera HAL exposes the camera (PackageManager.FEATURE_CAMERA_EXTERNAL); most phones do not, so USB webcams usually need UsbManager + a userspace UVC driver. https://developer.android.com/reference/androidx/camera/core/CameraSelector , https://groups.google.com/a/android.com/g/camerax-developers/c/0Q5DHEE-FZo , https://developer.android.com/training/camera2/camera-enumeration

## ANDROID 2. AudioRecord
- AudioSource.MIC = plain mic; VOICE_COMMUNICATION = "tuned for voice communications such as VoIP ... take advantage of echo cancellation or automatic gain control if available" (from javadoc, page did not render for fetch; quoted from memory). https://developer.android.com/reference/android/media/MediaRecorder.AudioSource
- ENCODING_PCM_16BIT is the guaranteed encoding; 44100 Hz guaranteed on all devices. getMinBufferSize(rate, channelConfig, encoding) = minimum for successful construction, "doesn't guarantee a smooth recording under load"; pick a multiple. read() blocks (READ_BLOCKING) -> run on a dedicated thread. setPreferredDevice(AudioDeviceInfo) API 23. https://developer.android.com/reference/android/media/AudioRecord
- Effects: AcousticEchoCanceler / NoiseSuppressor / AutomaticGainControl `.isAvailable()` then `.create(audioRecord.audioSessionId)`; some devices enable AEC by default with VOICE_COMMUNICATION. https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler
- AudioManager.setMode(MODE_IN_COMMUNICATION) for VoIP routing; API 31+ setCommunicationDevice / getAvailableCommunicationDevices; input listing getDevices(GET_DEVICES_INPUTS) -> AudioDeviceInfo (type, productName, id). https://developer.android.com/reference/android/media/AudioManager
- Sharing: Android 9 background apps get silence; Android 10+ priority sharing: two ordinary apps can't capture at once, one gets silence; VOICE_COMMUNICATION and CAMCORDER are "privacy-sensitive" and win; Android 11 setPrivacySensitive(true). Detect silencing via registerAudioRecordingCallback -> AudioRecordingConfiguration.isClientSilenced(). https://developer.android.com/media/platform/sharing-audio-input

## ANDROID 3. Permissions, background, indicators
- CAMERA and RECORD_AUDIO are dangerous runtime permissions (requestPermissions / ActivityResultContracts.RequestPermission). Android 11+: "Only this time" for location, microphone, camera; access while activity visible, briefly after backgrounding, or until an FGS started while visible stops; revocation kills the process; unused apps' permissions auto-reset. https://developer.android.com/training/permissions/requesting
- Android 9: background apps "cannot access the microphone or camera" (all apps regardless of targetSdk); idle UID's cameras are closed with an error (CameraDevice.StateCallback.onError, ERROR_CAMERA_DISABLED/DEVICE). https://developer.android.com/about/versions/pie/android-9.0-changes-all , https://developer.android.com/reference/android/hardware/camera2/CameraDevice.StateCallback
- FGS types `camera` / `microphone` (Android 14, targetSdk 34): manifest FOREGROUND_SERVICE + FOREGROUND_SERVICE_CAMERA / FOREGROUND_SERVICE_MICROPHONE, runtime CAMERA / RECORD_AUDIO granted first, else SecurityException. While-in-use: must startForegroundService while app has a visible activity (exemptions: notification/widget interaction, system component, etc.); not from BOOT_COMPLETED. https://developer.android.com/develop/background-work/services/fgs/service-types , https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
- Android 12 indicators: status-bar icon (green dot) when camera/mic in use; Quick Settings shows which apps. Global toggles (Quick Settings / Privacy): toggle off -> camera gives "a blank camera feed", mic gives "silent audio"; system re-prompts the user when an app opens the sensor. Check support: SensorPrivacyManager.supportsSensorToggle(Sensors.CAMERA|MICROPHONE). https://developer.android.com/training/permissions/explaining-access , https://developer.android.com/about/versions/12/behavior-changes-all
- adb: `adb shell pm grant <pkg> android.permission.CAMERA` / `RECORD_AUDIO` (or `adb install -g` grants all manifest runtime perms); `adb shell pm revoke ...`; `adb shell appops set <pkg> CAMERA allow|ignore` (RECORD_AUDIO op likewise). https://developer.android.com/tools/adb#pm
- adb sensor toggle: `adb shell cmd sensor_privacy enable|disable <USER_ID> camera|microphone` (help text in AOSP SensorPrivacyService; not run here). https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/sensorprivacy/SensorPrivacyService.java

## ANDROID 4. Emulator camera + mic
- `-camera-back MODE` / `-camera-front MODE` override the AVD. Modes (current doc): `emulated` (software-simulated camera), `environment` (virtual scene from AVD environment.ini; added 36.6.11, 2026-06-02, reloadable at runtime), `webcamN` (host webcam; `-webcam-list`), `imagefile:FILE`, `videofile:FILE`, `image360:FILE` (equirect, 36.6.4+), `none`. Older/AVD-config value `virtualscene` = 3D room (ARCore) scene. https://developer.android.com/studio/run/emulator-commandline , https://developer.android.com/studio/releases/emulator
  -> `videofile:` / `imagefile:` are the fixed-content test feeds (deterministic input for a capture leg). Exact first emulator version for them not found.
- AVD config.ini keys: `hw.camera.back` / `hw.camera.front` = none|emulated|virtualscene|webcam0 (Studio: "Emulated and VirtualScene produce a software-generated image"). https://developer.android.com/studio/run/managing-avds . Gotcha: runner passing `-camera-back virtualscene -no-window -gpu swiftshader_indirect` saw config.ini still say emulated/none (config.ini is not rewritten by CLI flags; the runtime file is hardware-qemu.ini), unresolved whether the scene rendered. https://github.com/ReactiveCircus/android-emulator-runner/issues/443
- `-no-window` defaults the renderer to SwiftShader; headless build since 28.0.25. https://developer.android.com/studio/releases/emulator . No authoritative statement found on whether virtualscene renders headless (it is a GL-rendered scene, so a software GPU should suffice; UNVERIFIED). `emulated`, `imagefile:`, `videofile:` need no GL scene, safest headless.
- Virtual scene content: console `virtualscene-image wall|table <path>` replaces the poster images; default poster at $SDK/emulator/resources/poster.png, layout in resources/Toren1BD.posters. https://developer.android.com/studio/run/emulator-console , https://medium.com/bliblidotcom-techblog/automate-custom-image-using-android-emulator-virtual-scene-camera-817086056fca
- Mic: since 28.0.3 host audio input is blocked by default; enable via Extended Controls > Microphone, `-allow-host-audio`, or `adb emu avd hostmicon` / `hostmicoff`. https://developer.android.com/studio/releases/emulator (29.0.6 notes)
- Feeding a file into the mic: gRPC `EmulatorController/injectAudio(stream AudioPacket)` (emulator started with `-grpc <port>`): first packet carries AudioFormat (samplingRate default 44100, Mono/Stereo, AUD_FMT_U8|S16 LE), 300 ms buffer, MODE_UNSPECIFIED blocks/paces to guest demand, MODE_REAL_TIME overwrites; FAILED_PRECONDITION if a microphone is already registered. So a WAV's PCM can be streamed in with no host audio device. https://android.googlesource.com/platform/external/qemu/+/refs/heads/emu-master-dev/android/android-grpc/services/emulator-controller/proto/emulator_controller.proto
- Alternative: hostmicon + route host default source (on linux: a PulseAudio/PipeWire virtual source playing the WAV). https://www.repeato.app/how-to-enable-microphone-input-in-the-android-emulator/

## LINUX 5. Camera portal (org.freedesktop.portal.Camera)
- Methods: AccessCamera(options{handle_token}) -> Request handle ("Request to gain access to the camera"); OpenPipeWireRemote(options) -> fd "to the PipeWire remote where the camera nodes are available", requires permission already granted; property IsCameraPresent (bool). https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Camera.html
- Source facts (xdg-desktop-portal main): permission store table "devices", id "camera" (shared/xdp-types.h). UNSET/ASK -> calls impl.portal.Access.AccessDialog on the backend ("Allow %s to Use the Camera?") and stores yes/no; Lockdown `disable-camera` refuses with NOT_ALLOWED; OpenPipeWireRemote refuses unless stored permission == YES. IsCameraPresent counts PipeWire nodes with media.class=Video/Source AND media.role=Camera, so a synthetic node must carry media.role=Camera to count. https://github.com/flatpak/xdg-desktop-portal/blob/main/desktop-portal/camera.c
- Pre-granting (tests): `flatpak permission-set devices camera <app-id> yes` writes the same store (flatpak CLI; not run here). https://docs.flatpak.org/en/latest/flatpak-command-reference.html#flatpak-permission-set . Host (non-flatpak) apps have an empty app id in the portal; how the store is keyed for them NOT verified.
- libportal: `xdp_portal_access_camera(portal, parent, flags, cancellable, cb, data)` + `_finish`; `xdp_portal_open_pipewire_remote_for_camera(portal)` -> fd; `xdp_portal_is_camera_present`. https://libportal.org/method.Portal.access_camera.html
- Needs a running xdg-desktop-portal plus a backend implementing Access (gnome / gtk / kde). Chromium documents exactly that requirement. https://github.com/andrewtheguy/wlshare/pull/21
- Non-flatpak apps use it too: Firefox (pref media.webrtc.camera.allow-pipewire, Firefox 116+, default on Fedora 41) goes portal -> WirePlumber -> v4l2/libcamera; author: portals now used by unsandboxed apps for the PipeWire camera. https://jgrulich.cz/2024/12/13/when-your-webcam-doesnt-work-solving-firefox-and-pipewire-issues/ . Chromium: flag `--enable-features=WebRtcPipeWireCamera` (merged M127, working M128). https://jgrulich.cz/tag/pipewire/
- No portal / no backend (bare container): the D-Bus call fails; an UNSANDBOXED app can connect to the PipeWire daemon socket ($XDG_RUNTIME_DIR/pipewire-0) directly and see every node. Snapshot does this: "tries to use the portal and if it fails either on the portal or on pipewire side, it will just use pipewire directly." https://gitlab.gnome.org/GNOME/Incubator/Submission/-/work_items/5 . Direct V4L2 (/dev/video*) also works for host apps, no consent UI at all.
- Microphone: no portal. Audio goes through PulseAudio/PipeWire-pulse directly; flatpak `--socket=pulseaudio` "includes sound input (mic), sound output/playback"; webcams outside the portal need `--device=all`. https://docs.flatpak.org/en/latest/sandbox-permissions.html

## LINUX 6. GStreamer
- Sources: `pipewiresrc` (in PipeWire's tree, not gst-plugins-*; props target-object, path (old), fd (portal remote), stream-properties, client-name, always-copy, keepalive-time, autoconnect, on-disconnect). https://gitlab.freedesktop.org/pipewire/pipewire/-/blob/master/src/gst/gstpipewiresrc.c . `v4l2src device=/dev/videoN` (gst-plugins-good) https://gstreamer.freedesktop.org/documentation/video4linux2/v4l2src.html . `libcamerasrc` (in libcamera's tree) https://libcamera.org/getting-started.html
- Device listing: GstDeviceMonitor / `pipewiredeviceprovider` (accepts the portal fd via `fd`, needs PipeWire >= 0.3.64), filter class Video/Source. Aperture device_provider.rs: https://gitlab.gnome.org/GNOME/snapshot/-/blob/main/aperture/src/device_provider.rs
- Preview: `gtk4paintablesink` (gst-plugins-rs gtk4) exposes a read-only `paintable` (GdkPaintable) for GtkPicture; GL textures need GTK >= 4.6, dmabuf GTK >= 4.14; wrap in glsinkbin when the paintable has a GL context. https://gstreamer.freedesktop.org/documentation/gtk4/index.html
- Frames to app code: `appsink` (new-sample, caps e.g. video/x-raw,format=RGBA) https://gstreamer.freedesktop.org/documentation/app/appsink.html
- Audio: `pulsesrc` https://gstreamer.freedesktop.org/documentation/pulseaudio/pulsesrc.html or `pipewiresrc` on an Audio/Source node. Synthetic: `videotestsrc` https://gstreamer.freedesktop.org/documentation/videotestsrc/ , `audiotestsrc` https://gstreamer.freedesktop.org/documentation/audiotestsrc/
- Prior art GNOME Snapshot (Rust, GTK4/libadwaita) with its in-tree `aperture` crate ("GTK Widget for cameras using gstreamer and pipewire"): `camerabin` with viewfinder-sink = tee -> gtk4paintablesink (glsinkbin if GL, else videoconvert), separate video/image filters, pipewiredeviceprovider fed the portal fd; libcamera-specific paths via api.libcamera.location. https://gitlab.gnome.org/GNOME/snapshot/-/blob/main/aperture/src/viewfinder.rs , https://gitlab.gnome.org/GNOME/snapshot/-/blob/main/aperture/README.md

## LINUX 7. Synthetic devices in a container
- v4l2loopback is an out-of-tree kernel module: loading needs the HOST kernel (container --privileged, --cap-add=ALL, -v /lib/modules) and a module built for that exact kernel; not possible unprivileged. On a mac, docker's Linux VM kernel would need the module built for it. https://github.com/v4l2loopback/v4l2loopback , https://www.baeldung.com/linux/docker-container-kernel-modules
- Userspace replacement: a PipeWire virtual camera from GStreamer, no kernel driver: `gst-launch-1.0 videotestsrc ! video/x-raw,format=YUY2 ! pipewiresink mode=provide stream-properties="properties,media.class=Video/Source,media.role=Camera" client-name="Virtual Camera"`; Firefox lists it. Swap videotestsrc for filesrc/decodebin for fixed content. https://www.ideasonboard.com/news/pipewire-is-the-new-v4l2loopback/ (pipewiresink modes default/render/provide: gstpipewiresink.c https://gitlab.freedesktop.org/pipewire/pipewire/-/blob/master/src/gst/gstpipewiresink.c)
  -> media.role=Camera is also what the portal's IsCameraPresent counts (see 5).
- PipeWire headless in a container without systemd: needs XDG_RUNTIME_DIR (and a D-Bus session bus for wireplumber); start `pipewire`, `wireplumber`, `pipewire-pulse` as background processes, DISABLE_RTKIT=y. https://walkergriggs.com/2022/12/03/pipewire_in_docker/ , https://github.com/mviereck/x11docker/wiki/Container-sound:-ALSA-or-Pulseaudio
- Virtual mic: `pactl load-module module-null-sink media.class=Audio/Source/Virtual sink_name=my-source channel_map=front-left,front-right` (works under pipewire-pulse), or a pipewire.conf.d `context.objects` adapter with `factory.name=support.null-audio-sink` + `media.class=Audio/Source/Virtual`; feed it by linking a player's output to its input_* ports (pw-link), or use module-loopback / `pw-loopback`. Classic PulseAudio route: null sink + its `.monitor` as the capture source. https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Virtual-Devices
  -> Untested shortcut by analogy with the video case: `filesrc location=x.wav ! wavparse ! audioconvert ! pipewiresink mode=provide stream-properties="p,media.class=Audio/Source"` (UNVERIFIED).

## LINUX 8. GTK4 itself
- GtkMediaStream is playback-only (GtkMediaFile implementation; play/pause/seek/volume, GdkPaintable); no camera, capture or microphone API anywhere in the GTK4 docs; capture means GStreamer (+ portal) beside GTK. https://docs.gtk.org/gtk4/class.MediaStream.html , https://docs.gtk.org/gtk4/class.MediaFile.html

# Camera and microphone capture on macOS and iOS (research 2026-10-01)

Research notes behind docs/capture-plan.md, web only (2026-10-01): no camera or microphone was opened on any host, VM, emulator or simulator for them. Bracketed notes mark inference.


Docs JSON prefix: D = https://developer.apple.com/tutorials/data/documentation/avfoundation/

## 1. Session, devices, notifications
- AVCaptureSession: inputs (AVCaptureDeviceInput) -> outputs; startRunning() BLOCKS, call on a serial background queue; batch changes in beginConfiguration()/commitConfiguration(). D/avcapturesession.json
- Device types (per-constant JSON): .external macOS 14 / iOS 17 (on iPad = UVC devices); .microphone macOS 14 / iOS 17 (replaces deprecated .builtInMicrophone; on iOS ONE microphone device, the audio route picks the physical mic and localizedName changes); .continuityCamera macOS 14 / iOS 17; .externalUnknown deprecated (old name for external); also .deskViewCamera. D/avcapturedevice/devicetype-swift.struct/{external,microphone,continuitycamera}.json
- On macOS 13 continuity cameras appeared under old types; .continuityCamera type is macOS 14+. isContinuityCamera, companionDeskViewCamera exist. D/avcapturedevice/systempreferredcamera.json
- AVCaptureDevice.systemPreferredCamera: macOS 13+, iOS 17+, read-only, KVO-observable; apps "should always KVO observe" it and swap the session input; nil only if no camera. Takes userPreferredCamera, suspension and Continuity Cameras into account. D/avcapturedevice/systempreferredcamera.json
- userPreferredCamera: macOS 13+, iOS 17+, read/write; persists across launches and reboots; system keeps a short history so it always reports a PRESENT device; setting nil has no effect. D/avcapturedevice/userpreferredcamera.json
- AVCaptureDevice.wasConnectedNotification / wasDisconnectedNotification: macOS 10.7+, iOS 4+; object = the AVCaptureDevice. D/avcapturedevice/wasconnectednotification.json
- AVCaptureSession.runtimeErrorNotification (macOS 10.7+, iOS 4+), error in userInfo[AVCaptureSessionErrorKey]. D/avcapturesession/runtimeerrornotification.json
- wasInterruptedNotification: macOS 10.14+, iOS 4+; interruptionEndedNotification; reason in AVCaptureSessionInterruptionReasonKey, plus AVCaptureSessionInterruptionSystemPressureStateKey. D/avcapturesession/wasinterruptednotification.json
- InterruptionReason enum lists iOS/iPadOS 9+, Catalyst, tvOS, visionOS, NO macOS: videoDeviceNotAvailableInBackground, audioDeviceInUseByAnotherClient (phone call/alarm), videoDeviceInUseByAnotherClient (another capture session), videoDeviceNotAvailableWithMultipleForegroundApps (Slide Over / Split View / PiP on iPad), videoDeviceNotAvailableDueToSystemPressure (thermal), sensitiveContentMitigationActivated (SCVideoStreamAnalyzer; resume via continueStream). D/avcapturesession/interruptionreason.json
  - So on macOS the reason key is not a documented API; a mac arm sees interruptions/disconnects/runtime errors, not reasons.

## 2. AVCaptureVideoPreviewLayer
- Subclass of CALayer; properties session, connection, videoGravity (AVLayerVideoGravity, same type AVPlayerLayer uses: resizeAspect / resizeAspectFill / resize), isPreviewing; init(sessionWithNoConnection:) for manual connections; layerPointConverted(fromCaptureDevicePoint:) / captureDevicePointConverted(fromLayerPoint:) for tap-to-focus. macOS 10.7+, iOS 4+. D/avcapturevideopreviewlayer.json
  - As a CALayer it sits in the layer tree like AVPlayerLayer: cornerRadius+masksToBounds clipping and sibling/overlay layers or views composite normally (standard CALayer behaviour; AVCam's PreviewView hosts it as a UIView's layerClass). D/avcapturevideopreviewlayer.json
- Mirroring is on the layer's AVCaptureConnection: automaticallyAdjustsVideoMirroring default TRUE (isVideoMirrored may flip when the input device changes; front camera preview mirrored by default); set it false then isVideoMirrored manually; check isVideoMirroringSupported. macOS 10.7+. D/avcaptureconnection/automaticallyadjustsvideomirroring.json
- Rotation: AVCaptureDevice.RotationCoordinator(device:previewLayer:), iOS 17 / macOS 14; KVO videoRotationAngleForHorizonLevelPreview -> previewLayer.connection.videoRotationAngle; videoRotationAngleForHorizonLevelCapture for data/photo outputs. D/avcapturedevice/rotationcoordinator.json
- Screenshots: in-process snapshots (CALayer.render(in:), UIView.drawViewHierarchy) return BLACK/blank for hardware video layers (AVSampleBufferDisplayLayer, AVPlayerViewController; same class as the preview layer). https://developer.apple.com/forums/thread/693299 , https://developer.apple.com/forums/thread/692859
  - Window-server captures (screencapture, ScreenCaptureKit, CGWindowListCreateImage, simctl io screenshot, device screen recording) composite the layer and do show it, as they do AVPlayerLayer [no single Apple doc found stating it; infer from compositing model]. A harness that wants pixels should read the data output, not snapshot the view.
  - Debug View Hierarchy shows the view, not the preview layer. https://developer.apple.com/forums/thread/772130

## 3. Data outputs
- AVCaptureVideoDataOutput.setSampleBufferDelegate(_:queue:) requires a SERIAL queue the app supplies; alwaysDiscardsLateVideoFrames default TRUE; videoSettings[kCVPixelBufferPixelFormatTypeKey]; availableVideoPixelFormatTypes. D/avcapturevideodataoutput.json
- captureOutput(_:didOutput:from:): CMSampleBuffer; buffers reference a limited device pool; retaining too many/too long starves the pool and frames are DROPPED (captureOutput(_:didDrop:from:)); copy if kept long. D/avcapturevideodataoutputsamplebufferdelegate/captureoutput(_:didoutput:from:).json
- Pixel formats (TN3121): native '420v' (8-bit video range biplanar), '420f' (full range), 'x420'/'x422' (10-bit); 'BGRA' is a conversion by AVCapture, ~2.6x memory of 420v; also compressed lossy '-8v0'. Pick BGRA only if consumer needs it. https://developer.apple.com/documentation/technotes/tn3121-selecting-a-pixel-format-for-an-avcapturevideodataoutput
  - Capture CVPixelBuffers are IOSurface-backed (zero-copy to Metal via CVMetalTextureCache) [general CoreVideo knowledge; TN3121 does not say].
- AVCaptureAudioDataOutput: same delegate+queue pattern; default output uncompressed PCM. audioSettings is macOS-ONLY (10.7+); nil = device native format (typically Float32 non-interleaved LPCM on mac). On iOS no audioSettings: format is the device's (typically 16-bit int LPCM; read the CMAudioFormatDescription). D/avcaptureaudiodataoutput.json , D/avcaptureaudiodataoutput/audiosettings.json
- Preview layer + video data output in one session: supported (AVMultiCamPiP uses two VideoDataOutputs and two preview layers in one session). https://asciiwwdc.com/2019/sessions/225
- AVCaptureMultiCamSession: iOS 13+, NOT macOS; isMultiCamSupported, hardwareCost, systemPressureCost; preset always inputPriority; use addInputWithNoConnections. D/avcapturemulticamsession.json
- Mac: "We've supported MultiCam on the Mac since ... Lion" (multiple sessions/cameras in one app); "on iOS, AVFoundation still limits clients to one active camera at a time" and no multiple sessions with multiple cameras in an app (WWDC19 225). https://asciiwwdc.com/2019/sessions/225

## 4. Permissions
- AVCaptureDevice.authorizationStatus(for: .video/.audio): .notDetermined / .restricted (parental controls, MDM) / .denied / .authorized; requestAccess(for:) (async or completion) prompts only while notDetermined, otherwise returns the stored answer. Required on iOS and macOS 10.14+. D/requesting-authorization-to-capture-and-save-media.json
- Info.plist NSCameraUsageDescription / NSMicrophoneUsageDescription; Apple: the key "and the appropriate entitlement enabled in macOS" must exist before requesting or using a device, "Otherwise, the system terminates your app." (applies to iOS AND macOS). same URL
- macOS entitlements: com.apple.security.device.camera (App Sandbox OR Hardened Runtime; "built-in and external cameras"); com.apple.security.device.audio-input (Hardened Runtime, "Resource Access > Audio Input"; also Core Audio input); com.apple.security.device.microphone (App Sandbox, "Hardware > Audio Input"). An unsigned / non-hardened dev binary needs no entitlement. https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.camera , .../com.apple.security.device.audio-input , .../com.apple.security.device.microphone
- Unbundled CLI on macOS: TCC attributes the request to the RESPONSIBLE process (nearest bundle ancestor, e.g. Terminal.app / kitty); its Info.plist must carry the usage key; a CLI from Terminal inherits Terminal's grant. If the responsible app lacks the key, denial is SILENT (no prompt; requestAccess -> false) and tccutil reset does not help. https://github.com/OpenCoven/coven-cave/issues/5696
- A CLI may embed an Info.plist in a __TEXT,__info_plist section (Xcode "Create Info.plist Section in Binary", or ld -sectcreate __TEXT __info_plist) with CFBundleIdentifier + NSCameraUsageDescription. Camera does not work over SSH (non-GUI login session) - Quinn. https://developer.apple.com/forums/thread/111100
  - kaya relevance: mac guests hosted by python3 / dotnet / java / a cargo binary launched from a lane runner get the grant of whatever app is responsible (Terminal, or the launchd-run lane's parent); an ssh-launched leg will not get camera at all.
- Reset: `tccutil reset Camera [bundle-id]`, `tccutil reset Microphone [bundle-id]` (services named Camera, Microphone). https://danielcosenza.com/posts/mac-howto-tccutil-privacy-permissions/
- iOS simulator: `simctl privacy <dev> grant microphone <bundle>` exists; Xcode 26.6 `simctl privacy` lists NO camera service (calendar, contacts, location, photos, media-library, microphone, motion, reminders, siri). Measured locally 2026-10-01 with Xcode-26.6.0.app (help text only).

## 5. Privacy indicators
- Mac: built-in camera indicator LED glows green; "engineered so that it can't activate without the camera indicator light also turning on" (hardware-tied). https://support.apple.com/guide/mac-help/use-the-camera-mchlp2980/mac
- Mac menu bar dot next to Control Center: orange = microphone, green = camera, purple = system audio recording; only one dot shown at a time; Control Center lists the apps using them. https://support.apple.com/guide/mac-help/quickly-change-settings-mchl50f94f8f/mac ; can be hidden on external displays (MDM) https://support.apple.com/en-us/118449
- iOS 14+: orange dot (orange square with Differentiate Without Color) = microphone; green dot = camera or camera+mic; Control Center names the app. https://support.apple.com/en-us/108331
- Apps cannot suppress these; they are system UI (a toolkit need not draw its own indicator).

## 6. iOS simulator
- No camera: apps discover no capture device; AVCaptureDevice.default(for: .video) returns nil. No Apple announcement of simulator camera support found through Xcode 26 (searched release notes/WWDC25). https://www.rocketsim.app/docs/features/capturing/simulator-camera-support/ , https://github.com/MarioB03/simcam
- What people use:
  - RocketSim (paid Mac app): creates a real AVCaptureDevice "RocketSimCaptureDevice" inside the sim app via "RocketSim Connect" (a debug-only bundle the app loads); streams the Mac camera; one camera only (front/back switch does nothing), Mac resolution, no audio, DataScannerViewController unsupported. https://www.rocketsim.app/docs/features/capturing/simulator-camera-support/ , https://www.avanderlee.com/xcode/simulator-camera-test-your-app-without-a-physical-device/
  - simcam: DYLD_INSERT_LIBRARIES dylib (launched via simctl env) swizzling AVCaptureSession, AVCaptureDevice, AVCaptureVideoPreviewLayer, AVCaptureMetadataOutput; feeds screen frames. https://github.com/MarioB03/simcam
  - SimulatorCamera (dautovri): a CMIOExtension system extension on the HOST; README claims the iOS Simulator (Xcode 16+, macOS 14+) discovers host virtual cameras as "SimulatorCamera Virtual" with zero app changes. UNVERIFIED, contradicts the "no camera" consensus; would need a measurement before relying on it. https://github.com/dautovri/SimulatorCamera
  - Others: CamBridge, iCimulator, FauxCam, Buoy (most are in-app SDKs or injection). https://github.com/engelon/CamBridge , https://github.com/YuigaWada/iCimulator , https://buoy.gg/camera
  - Standard practice otherwise: app-side protocol around the capture source with a mock that emits synthetic CVPixelBuffers.
- Simulator MICROPHONE: works, routed from a host audio device; the Simulator's hardware (I/O) menu picks the input and output device (WWDC19 418 Q&A). The host-side TCC prompt/grant belongs to Simulator.app (responsible process) [inference]. https://developer.apple.com/videos/play/wwdc2019/418/
  - Consequence: a sim mic leg needs a host input; with a virtual input (BlackHole) selected in that menu it can be fed deterministic audio.

## 7. Virtual devices on macOS (for a camera lane)
- Camera Extension (CMIOExtension: Provider / Device / Stream), macOS 12.3+, a system extension packaged inside a host app; host app needs com.apple.developer.system-extension.install + app-sandbox + an App Group; activated with OSSystemExtensionRequest.activationRequest(forExtensionWithIdentifier:queue:) via OSSystemExtensionManager.shared.submitRequest; host app MUST be in /Applications; the user approves in System Settings (admin). Apple's sample discovers it with DiscoverySession(.externalUnknown); on macOS 14+ that is .external. D/../coremediaio/creating-a-camera-extension-with-core-media-i-o.json (https://developer.apple.com/documentation/coremediaio/creating-a-camera-extension-with-core-media-i-o)
- Extension runs as its own daemon under role user _cmiodalassistants, tighter sandbox (no fork/exec, no window server); appears to every app (FaceTime, QuickTime, Photo Booth) like a real camera; SINK streams let an app push CMSampleBuffers into the extension (the OBS-style virtual camera); deleting the host app uninstalls it. TCC consent still required for the consuming app. https://developer.apple.com/videos/play/wwdc2022/10022/
- `systemextensionsctl developer on` lifts the /Applications requirement (needs SIP disabled); `systemextensionsctl reset` / list. MDM can pre-approve via a system-extension policy payload. https://derflounder.wordpress.com/2020/09/01/uninstalling-macos-system-extensions/ , https://developer.apple.com/forums/thread/117481
- DAL plug-ins: deprecated 12.3, disabled from macOS 14.1 (Sonoma got a grace through 14.0); they loaded in-process in the client app. https://eclecticlight.co/2023/10/27/how-sonoma-14-1-could-stop-your-camera-working/ , https://developer.apple.com/videos/play/wwdc2022/10022/
- No public way to make AVCaptureDevice enumerate a synthetic camera without a CMIO extension (or a physical/continuity device); AVCaptureDevice cannot be instantiated or subclassed into a session by apps. Alternatives: (a) app-side mock source behind the toolkit's own capture abstraction emitting CVPixelBuffers; (b) in-process swizzling/DYLD injection (simcam's approach, test-only). https://github.com/MarioB03/simcam
- Virtual audio input: AudioServerPlugIn (userspace HAL driver hosted by coreaudiod in its own sandboxed helper) installed to /Library/Audio/Plug-Ins/HAL (root-owned, needs sudo); BlackHole (GPL-3.0; brew install blackhole-2ch|16ch|64ch) then `sudo killall -9 coreaudiod` to load (older reports say Catalina needed a reboot). Loopback: what is played to BlackHole output appears on BlackHole input, so a test can feed a known tone. https://github.com/ExistentialAudio/BlackHole , https://theevilbit.github.io/beyond/beyond_0013/ , https://github.com/kyleneideck/BackgroundMusic/blob/master/DEVELOPING.md
  - On macOS every Core Audio input device (incl. BlackHole, aggregate devices) is listed by AVCaptureDevice as a .microphone device [general knowledge; not fetched]. No root needed to CREATE an aggregate device (AudioHardwareCreateAggregateDevice), but it still needs a real or plug-in input underneath.

## 8. Foreground / activation policy
- iOS: camera stops when the app backgrounds (interruption videoDeviceNotAvailableInBackground); iPad Split View/Slide Over/PiP/Stage Manager interrupt with videoDeviceNotAvailableWithMultipleForegroundApps unless isMultitaskingCameraAccessEnabled (iOS 16+, entitlement com.apple.developer.avfoundation.multitasking-camera-access, set before startRunning). D/avcapturesession/interruptionreason.json , D/avcapturesession/ismultitaskingcameraaccessenabled.json
- iOS microphone may continue in background only with the `audio` UIBackgroundModes and an active AVAudioSession [general knowledge].
- macOS: the interruption reasons are not defined on macOS; there is no foreground requirement for capture. Menu-bar-only (LSUIElement, i.e. .accessory) camera apps ship (e.g. Hand Mirror, Glance), so a .accessory process can run AVCaptureSession and a preview layer. The first-use TCC prompt is system UI and does not need the app frontmost [inference]. https://medium.com/@kcrdissanayake/the-macos-camera-app-that-finally-lives-in-your-menu-bar-no-recording-no-fuss-733b778bc418 , https://benoitpasquier.com/webcam-utility-app-macos-swiftui/
- macOS: WWDC19 225 says only that the Mac has supported multiple cameras at once since Lion. That several apps can open the SAME camera at once on macOS (FaceTime and Photo Booth together) is common experience, not an Apple doc [unverified; measure before relying on it]. On iOS a second client interrupts with videoDeviceInUseByAnotherClient. https://asciiwwdc.com/2019/sessions/225
- Not over SSH: capture needs a GUI login session (Quinn). https://developer.apple.com/forums/thread/111100

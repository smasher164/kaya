# Semantic colour and shape tokens: vendor-doc verification (2026-09-25)

Status: complete. Each row: claim, verdict (CONFIRMED / WRONG / UNVERIFIED), fact, source.

Doc JSON endpoints are Apple's `https://developer.apple.com/tutorials/data/documentation/<path>.json` (the rendered pages are JS-only).

## 1. Apple (SwiftUI / AppKit / UIKit)

| Claim | Verdict | Fact / note | Source |
|---|---|---|---|
| `Color.accentColor` exists | CONFIRMED | iOS 13+, macOS 10.15+, all Apple platforms; not deprecated. On macOS the app's asset-catalog accent is applied only when the user picks Multicolor in General > Accent color; otherwise the user's choice replaces it. | https://developer.apple.com/documentation/swiftui/color/accentcolor ; HIG https://developer.apple.com/design/human-interface-guidelines/color |
| `systemGreen`/`systemOrange`/`systemRed` adapt to dark mode | CONFIRMED | UIColor: "automatically adapts to the current trait environment" (iOS 7+). NSColor: "automatically adapts to vibrancy and accessibility settings" (macOS 10.10+). | https://developer.apple.com/documentation/uikit/uicolor/systemgreen ; https://developer.apple.com/documentation/appkit/nscolor/systemgreen |
| ...and to Increase Contrast | CONFIRMED | HIG: system colours "define variants for all these contexts"; "With the Increase Contrast setting turned on, the color differences become far more apparent." Custom colours must supply light, dark and an increased-contrast option for each. | HIG color (above) |
| `secondarySystemFill` / fill family on iOS | CONFIRMED | UIColor `systemFill`...`quaternarySystemFill`, iOS 13+ ("overlay fill color for medium-size shapes"). | https://developer.apple.com/documentation/uikit/uicolor/secondarysystemfill |
| ...and on macOS (14+?) | CONFIRMED, macOS 14.0 | NSColor `systemFill`, `secondarySystemFill`, `tertiarySystemFill`, `quaternarySystemFill` AND a fifth, `quinarySystemFill` (macOS-only), all introduced macOS 14.0. NOTE the size semantics differ from iOS: NSColor secondary = "small-size shapes, such as the backing of a progress indicator"; UIColor secondary = "medium-size shapes". SwiftUI's cross-platform spelling is `ShapeStyle.fill` (`FillShapeStyle`, with `.secondary`/`.tertiary`/`.quaternary` levels), iOS 17 / macOS 14. There is no `Color.secondarySystemFill` in SwiftUI; use `.fill.secondary` or `Color(uiColor:)`/`Color(nsColor:)`. | https://developer.apple.com/documentation/appkit/nscolor/secondarysystemfill ; https://developer.apple.com/documentation/swiftui/shapestyle/fill |
| `Color(red:green:blue:)` does not adapt unless from an asset catalog with appearance variants | CONFIRMED, with one omission | SwiftUI Color overview: late resolution "enables a context-dependent appearance for system defined colors, or those that you load from an Asset Catalog"; component-built colours are constants. OMISSION: a dynamic platform colour also adapts — `UIColor(dynamicProvider:)` / `NSColor(name:dynamicProvider:)` wrapped in `Color(uiColor:)`/`Color(nsColor:)` — so an asset catalog is not the only route. | https://developer.apple.com/documentation/swiftui/color |
| Text colour on an accent fill | PARTLY UNVERIFIED | iOS/SwiftUI: no public "on-accent" semantic colour exists; the system's own filled controls (`.borderedProminent`) draw white labels, but no doc states a token. macOS: `NSColor.alternateSelectedControlTextColor` ("text in a selected control", table/list equivalent of `selectedControlTextColor`; not deprecated, though its sibling `alternateSelectedControlColor` is) is the text colour AppKit pairs with `selectedContentBackgroundColor` (macOS 10.14, the accent-derived selection fill). The pairing is convention; the `selectedContentBackgroundColor` page names no text colour. HIG says nothing about text on accent. | https://developer.apple.com/documentation/appkit/nscolor/alternateselectedcontroltextcolor ; https://developer.apple.com/documentation/appkit/nscolor/selectedcontentbackgroundcolor |

## Summary of corrections for the design doc

1. macOS fill colours need macOS 14; NSColor has a fifth level `quinarySystemFill`, and NSColor/UIColor describe the levels with DIFFERENT shape sizes. SwiftUI spells them `.fill`/`.fill.secondary` (iOS 17 / macOS 14), not `Color.secondarySystemFill`.
2. Asset catalogs are not the only adaptive route on Apple: dynamic-provider UIColor/NSColor adapt too.
3. No public "text on accent" colour on iOS; on macOS `alternateSelectedControlTextColor` is the closest semantic, by convention.
4. Compose has no harmonize API; MDC-Android's `MaterialColors` or material-color-utilities' `Blend` must be called from Compose via ARGB ints.
5. libadwaita CSS variables arrived in 1.6; the named colours remain defined (variables are initialised from them) in 1.6, 1.7 and main. Card radius is 12px in every version checked, as a SCSS constant, not a readable variable.
6. WinUI High Contrast collapses Success/Caution/Critical/Attention to one colour (`SystemColorWindowTextColor`) and the accent fill to `SystemColorWindowColor`; a design that signals severity by colour alone loses it in HC. `HighContrastAdjustment` (default on) overrides hard-coded text colour but not hard-coded fills.
